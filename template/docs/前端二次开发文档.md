## 第一章 开发环境准备

本章将指导你从零开始搭建项目的开发环境。在正式编写业务代码之前，请务必按照本章的步骤完成所有准备工作，避免因环境问题导致不必要的错误。

### 1.1 系统要求

#### 1.1.1 Node.js 版本要求

本项目在 `package.json` 中通过 `engines` 字段明确限定了 Node.js 的最低版本要求：

```json
"engines": {
  "node": ">=22",
  "npm": ">= 10"
}
```

**你必须使用 Node.js 22 或更高版本。** 如果使用低于该版本的 Node.js，在执行 `npm install` 时可能遇到依赖解析失败、`node-sass` / `sass` 编译错误等问题。这是因为项目中使用的 `sass: ~1.32.12` 以及部分 Webpack 4 插件对 Node.js 版本有硬性要求。

**安装方式：**

推荐前往 [Node.js 官方网站](https://nodejs.org/) 下载 LTS（长期支持版）安装包。安装完成后，打开终端验证版本：

```bash
node -v
# 应输出 v22.x.x 或更高

npm -v
# 应输出 10.x.x 或更高
```

#### 1.1.2 推荐使用 nvm 管理多版本 Node

如果你的电脑上需要同时维护多个项目，而不同项目要求不同的 Node 版本，强烈推荐使用 **nvm**（Node Version Manager）来管理多版本 Node.js。

**Windows 用户** 应使用 [nvm-windows](https://github.com/coreybutler/nvm-windows)。安装完成后：

```bash
# 安装 Node 18
nvm install 22

# 切换到 Node 18
nvm use 22

# 确认当前版本
node -v
```

**注意事项：** 每次打开新的终端窗口时，请确认当前使用的 Node 版本是否正确。如果你发现 `npm run dev` 报错，请先检查 Node 版本。

#### 1.1.3 包管理器规范

本项目统一使用 **npm** 作为包管理器。项目根目录下存在 `package-lock.json` 文件，该文件精确锁定了每个依赖包的版本号和依赖树结构。**请勿使用 yarn 安装依赖**，否则会生成 `yarn.lock` 文件并可能导致依赖版本冲突。

特别说明，项目的 `postinstall` 脚本配置了 `patch-package`：

```json
"scripts": {
  "postinstall": "patch-package"
}
```

这意味着每次执行 `npm install` 后，会自动执行 `patch-package`，该工具会读取项目根目录下 `patches/` 目录中的 `.patch` 文件，对 `node_modules` 中的某些第三方库进行定向修补。这是一种常见的在不 fork 第三方库的前提下修复 bug 或定制行为的方式。**如果你手动删除了 `node_modules` 后重新安装依赖，这些补丁会自动重新生效，无需额外操作。**

### 1.3 项目初始化

#### 1.3.1 克隆与依赖安装

```bash
# 1. 克隆仓库
git clone <仓库地址>

# 2. 安装依赖（请务必使用 npm，不要使用 yarn）
```

安装过程通常需要 2-5 分钟，取决于网络速度。安装完成后，你会看到终端输出 `patch-package` 的补丁执行日志，这是正常现象。

#### 1.3.2 patch-package 补丁机制详解

上文提到，`npm install` 完成后会自动运行 `patch-package`。此工具的工作原理是：

1. 你在 `node_modules` 中直接修改某个第三方库的源码来修复 bug。
2. 运行 `npx patch-package <包名>` 生成一个 `.patch` 差异文件，保存到 `patches/` 目录。
3. 以后每次 `npm install`，`postinstall` 钩子会自动将这些补丁应用回去。

**如果你在开发过程中发现某个第三方库存在 bug 需要修复：**

```bash
# 1. 直接进入 node_modules 修改对应文件
# 2. 修改完成后，执行以下命令生成补丁
npx patch-package <包名>
# 例如：npx patch-package element-ui

# 3. 将生成的 patches/ 目录下的 .patch 文件提交到 Git
```

#### 1.3.3 常见安装问题与解决方案

| 问题 | 原因 | 解决方案 |
|---|---|---|
| `node-sass` 安装失败 | 本项目使用的是 `sass: ~1.32.12`（Dart Sass），不是 `node-sass`。如果其他项目引入了 `node-sass`，可能有冲突 | 确保没有全局安装 `node-sass`，本项目仅依赖 `sass` 和 `sass-loader` |
| 安装速度极慢 | npm 默认源在国外 | 设置淘宝镜像源：`npm config set registry https://registry.npmmirror.com` |
| `postinstall` 报错 | `patch-package` 补丁与当前依赖版本不匹配 | 先删除 `node_modules`，再执行 `npm install` |
| 运行报 `Cannot find module` | 依赖未完整安装 | 删除 `node_modules` 和 `package-lock.json`，重新 `npm install` |

### 1.4 开发服务启动

#### 1.4.1 本地启动命令

```bash
npm run dev
```

该命令对应 `package.json` 中的 `scripts.dev`，实际执行 `node src/libs/start.mjs && vite`。启动后，开发服务器监听端口 **9527**（在 `vite.config.ts` 的 `server.port` 中配置）：

```typescript
server: {
  host: true,
  port: 9527,
  // ...
}
```

启动成功后，在浏览器中访问 `http://localhost:9527/admin`。注意这里的 `/admin` 路径前缀是通过 `src/settings.js` 中的 `roterPre` 参数控制的。该路径前缀会影响前端路由的所有路径以及开发服务器的初始重定向逻辑。`vite.config.ts` 中用一个自定义插件（`redirectRootPlugin`）实现了访问根路径 `/` 时自动重定向到 `/admin`，等价于原 `devServer.before` 钩子：

```typescript
configureServer(server) {
  server.middlewares.use((req, res, next) => {
    const url = (req.url || '').split('?')[0]
    if (url === '/') {
      res.writeHead(302, { Location: base })
      res.end()
      return
    }
    next()
  })
}
```

#### 1.4.2 开发代理配置详解

本项目在 `vue.config.js` 的 `devServer.proxy` 中配置了三组代理规则，用于将前端的 API 请求、文件上传请求和 WebSocket 连接转发到后端服务器：

```javascript
proxy: {
  // 代理规则 1：API 接口请求
  "^/api": {
    target: "http://dev.oa.crmeb.net",   // 后端 API 地址
    changeOrigin: true                    // 修改请求头中的 Origin，避免后端跨域拦截
  },
  // 代理规则 2：上传文件的资源访问
  "^/uploads": {
    target: "http://dev.oa.crmeb.net",
    changeOrigin: true,
    pathRewrite: {}
  },
  // 代理规则 3：WebSocket 连接
  "^/ws": {
    target: "http://dev.oa.crmeb.net",
    changeOrigin: true,
    ws: true                              // 启用 WebSocket 代理
  }
}
```

**二次开发说明：** 当你需要连接到不同的后端环境时（如本地后端、测试服务器、预发布服务器），只需修改上述三个 `target` 的值即可。注意三个代理规则的 `target` 应保持一致，否则可能出现 API 正常但 WebSocket 连不上的问题。

**`.env.production`（生产环境，随版本库提供）：**

`src/config/env.ts` 是全部环境变量的唯一出口，顺带完成默认值兜底与类型收敛（开关类变量直接导出 `boolean`，调用方不必各自写 `=== 'true'`）：

| 导出常量 | 对应环境变量 | 说明 |
|---|---|---|
| `BASE_API` | `VITE_BASE_API` | 后端 API 基础地址，留空则回落到当前站点 origin |
| `WS_URL` | `VITE_WS_URL` | WebSocket 地址，留空则依据接口地址推导 |
| `AI_BASE_URL` | `VITE_AI_BASE_URL` | AI 服务地址，留空则回落到接口地址 / 当前 origin |

| `DEMO_ACCOUNT` / `DEMO_PASSWORD` | `VITE_DEMO_ACCOUNT` / `VITE_DEMO_PASSWORD` | 演示站预填账号密码，仅 `build:demo` 由命令行注入 |

新增变量三步走：`.env.*` 里加 `VITE_XXX` → `src/types/env.d.ts` 补类型 → `src/config/env.ts` 导出一个语义化常量。

#### 1.4.4 接口基地址拼接逻辑

接口的基地址并不是直接使用 `BASE_API`，而是经过 `src/libs/settingMer.js` 的二次加工。这个文件是整个项目中所有网络请求的地址"源头"，理解它至关重要：

```javascript
// src/libs/settingMer.js
import Cookies from 'js-cookie';
import { processResourceUrl } from '@/utils/resourceUtil';
import { BASE_API, WS_URL } from '@/config/env';

// 请求接口地址 如果没有配置自动获取当前网址路径
const resolvedApiUrl = processResourceUrl(BASE_API || `${location.origin}`);

function getDefaultWsUrl() {
  const apiUrl = BASE_API || resolvedApiUrl;
  if (apiUrl) {
    try {
      const url = new URL(apiUrl, location.origin);
      url.protocol = url.protocol === 'https:' ? 'wss:' : 'ws:';
      return url.origin;
    } catch (e) {
      // ignore malformed env and fallback to current host
    }
  }
  return (location.protocol === 'https:' ? 'wss' : 'ws') + '://' + location.host;
}

const resolvedWsUrl = WS_URL || getDefaultWsUrl();

const SettingMer = {
  httpUrl: resolvedApiUrl,               // 服务器根地址
  https: resolvedApiUrl + '/api/ent',    // API 请求的完整基地址
  wsSocketUrl: resolvedWsUrl,            // WebSocket 连接地址
  title: login_title || 'OA系统-总后台',  // 网站标题
};

export default SettingMer;
```

**关键逻辑解析：**

1. **`resolvedApiUrl`**：如果 `BASE_API`（即 `VITE_BASE_API`）有值则使用该值，否则使用当前网站的 `location.origin`（即 `协议 + 域名 + 端口`）。这就是生产环境下 `VITE_BASE_API` 可以留空的原因 —— 系统会自动使用当前域名。取到的地址还会再经 `processResourceUrl` 加工：开发环境下剥掉 `http://dev.oa.crmeb.net` 前缀转为相对路径（走 Vite 代理），页面为 `https` 时把 `http://` 资源升级为 `https://`。

2. **`SettingMer.https`**：在 `resolvedApiUrl` 的基础上拼接了 `/api/ent`。因此所有 API 接口的完整路径格式为 `http://xxx.com/api/ent/<接口路径>`。当你在 `src/api/` 目录下的文件中调用 `request.get('user/menus')` 时，最终发出的请求地址是 `http://xxx.com/api/ent/user/menus`。

3. **`resolvedWsUrl`**：`WS_URL`（即 `VITE_WS_URL`）留空时，由 `getDefaultWsUrl()` 依据接口地址推导 —— 把 `http`/`https` 协议换成 `ws`/`wss`；接口地址不可用时再回落到当前页面的 host。

### 2.2 vue.config.js 完整配置解读

> ⚠️ **本节内容已过时。** 项目已从 vue-cli/webpack 迁移至 Vite，`vue.config.js` 连同 `babel.config.js`、`postcss.config.js`、`build/` 均已删除，构建配置全部收敛到根目录的 **`vite.config.ts`**。下面 2.2.1 已按 Vite 改写，其余小节（别名、分包、代理等）仍是 webpack 时代的描述，仅供理解历史设计意图，**不要照抄其写法**。当前的构建约定以 `AGENTS.md` 的「构建工具约定（Vite）」为准。

#### 2.2.1 输出与路径配置

```typescript
// vite.config.ts
export default defineConfig(({ mode }) => ({
  base: roterPre + '/',        // '/admin/'，等价于原 publicPath
  publicDir: 'public',
  build: {
    outDir: 'dist',            // 构建输出目录
    assetsDir: 'system',       // 静态资源子目录（dist/system/）
    sourcemap: false,          // 生产环境不生成 sourceMap
  },
}))
```

原 `lintOnSave` 已无对应配置：ESLint 不再接入 dev / build 流程，只在编辑器中做实时提示（详见 `AGENTS.md` 的「代码校验约定」）。

- **`publicPath`**：值为 `'/admin/'`。这意味着所有构建产出的资源引用路径都以 `/admin/` 为前缀。如果你部署到服务器的根路径，此值需要改为 `'/'`。该值来源于 `src/settings.js` 中的 `roterPre` 变量。
- **`assetsDir`**：设置为 `'system'`，构建后的 JS、CSS 等文件会存放在 `dist/system/` 目录下，而非 Webpack 默认的根目录。
- **`productionSourceMap`**：设置为 `false`，关闭了生产环境的 Source Map 生成。这是一个安全和性能的最佳实践 —— Source Map 会暴露原始源码，且增大构建体积。

#### 2.2.2 路径别名

```javascript
configureWebpack: {
  resolve: {
    alias: {
      '@': resolve('src'),         // 指向 src 目录
      '~@': resolve('static'),     // 指向 static 目录
    },
  },
},
```

- **`@`**：指向 `src/` 目录。在代码中使用 `import Foo from '@/components/Foo'` 等价于 `import Foo from 'src/components/Foo'`。这是 Vue 项目的标准约定。
- **`~@`**：指向项目根目录下的 `static/` 目录，用于引用不经 Webpack 处理的静态资源。

#### 2.2.3 SVG 图标加载配置

项目使用 `svg-sprite-loader` 将 SVG 文件合并为雪碧图，以实现高性能的图标方案：

```javascript
// 排除 src/icons 目录，让默认的文件加载器不处理该目录下的 SVG
config.module.rule('svg').exclude.add(resolve('src/icons')).end();

// 为 src/icons 目录下的 SVG 添加专用处理规则
config.module
  .rule('icons')
  .test(/\.svg$/)
  .include.add(resolve('src/icons'))
  .end()
  .use('svg-sprite-loader')
  .loader('svg-sprite-loader')
  .options({
    symbolId: 'icon-[name]',   // 图标 ID 格式为 icon-文件名
  });
```

**工作原理：** 当你把一个 SVG 文件（如 `dashboard.svg`）放入 `src/icons/svg/` 目录时，Webpack 会自动将它编译为 `<symbol id="icon-dashboard">` 并注入到 HTML 中。在页面上通过 `<svg-icon icon-class="dashboard" />` 组件即可使用。

#### 2.2.4 splitChunks 分包策略

生产环境下的代码分割策略，是影响首屏加载速度和缓存命中率的关键配置。本项目定义了 **9 个 cacheGroup**（缓存组），每个组的用途如下：

| 缓存组名 | 匹配规则 | 分块策略 | 优先级 | 用途说明 |
|---|---|---|---|---|
| `libs` | 所有 `node_modules` | `initial`（初始加载） | 10 | 将首次加载所需的第三方依赖打成一个包 |
| `elementUI` | `element-ui` | all | 20 | Element-UI 体积较大，单独拆分以利用浏览器缓存 |
| `asyncShared` | `node_modules` 中被 ≥2 个异步路由共用的模块 | `async` | 8 | 避免多个路由页面重复打包同一个依赖 |
| `wangeditor` | `@wangeditor/*` | `async` | 25 | 富文本编辑器很大（~500KB），按需加载 |
| `aceBuilds` | `ace-builds` | `async` | 25 | 代码编辑器组件，仅在需要时加载 |
| `echarts` | `echarts` / `zrender` / `echarts-liquidfill` | `async` | 25 | 图表库，仅在图表页面加载 |
| `simpleMindMap` | `simple-mind-map` | `async` | 25 | 思维导图组件，按需加载 |
| `xlsx` | `xlsx` | `async` | 25 | Excel 处理库，仅在导入导出时加载 |
| `commons` | `src/` 下除 `views/` 外被 ≥3 个模块引用的文件 | all | 5 | 提取通用业务代码 |

**二次开发须知：** 如果你新引入了一个体积较大（>100KB）的第三方库，建议在此处为其新增一个独立的 `cacheGroup`，防止它被打包进 `chunk-libs` 导致初始加载变慢。

#### 2.2.5 Moment.js 按需加载


## 第三章 路由与动态菜单机制

本项目的路由机制是整个前端架构中最核心、最复杂的模块之一。它实现了**基于后端菜单接口的动态路由注入**，配合 `require.context` 的组件自动发现机制，使得前端无需手动为每个页面编写路由配置。理解本章内容，是新增业务页面的前提。

### 3.1 路由整体架构

#### 3.1.1 路由基本信息

- **路由模式**：`history` 模式（URL 中不带 `#`，需要服务器配合 `try_files` 配置）
- **全局路由前缀**：`/admin`（由 `src/settings.js` 中的 `roterPre` 控制）
- **路由库版本**：`vue-router 3.0.2`

这意味着系统中所有页面的 URL 都以 `/admin` 开头。例如工作台的路径是 `/admin/user/work`，登录页的路径是 `/admin/login`。

#### 3.1.2 路由文件分工

路由相关的代码分布在 `src/router/` 目录下的三个文件中：

| 文件 | 行数 | 职责 |
|---|---|---|
| `index.js` | 157 行 | **路由核心**：创建路由实例、定义动态路由生成函数、组件自动发现 |
| `routes.js` | — | **通用静态路由表**：登录、工作台、错误页、文件预览等与具体业务模块无关的路由 |
| `modules/*.js` | — | **业务模块静态路由**：按业务域（`customer` / `develop` / `hr` / `inventory` / `program` / `setting` / `user`）拆分的固定路由，一个模块一个文件 |
| `modules/index.js` | — | **自动聚合**：通过 `require.context` 收集本目录下所有模块文件，新增模块无需改动 `router/index.js` |

它们在 `index.js` 中通过以下方式合并：

```javascript
import defaultRoutes from '@/router/routes';
// 按业务模块拆分的固定路由，见 @/router/modules
import moduleRoutes from '@/router/modules';
export const constantRoutes = [...defaultRoutes, ...moduleRoutes];
```

`constantRoutes` 是"常量路由"（静态路由），在应用启动时就会被注册。动态路由则在用户登录后，通过后端接口返回菜单数据再注入。

---

### 3.2 静态路由配置详解

#### 3.2.1 routes.js 中的路由清单

`src/router/routes.js` 定义了以下静态路由，这些路由不依赖后端菜单，始终可访问：

```javascript
const defaultRoutes = [
  // 1. 默认路由 - 工作台（首页）
  {
    path: roterPre,              // '/admin'
    component: Layout,           // 使用整体布局组件
    redirect: `${roterPre}/user/work`,
    children: [{
      path: `${roterPre}/user/work`,
      component: () => import('@/views/user/workbench/index'),
      name: 'dashboard-admin',
      meta: { title: '工作台', icon: 'dashboard' }
    }]
  },

  // 2. 登录页（不使用 Layout 布局）
  {
    path: `${roterPre}/login`,
    name: 'login',
    component: () => import('@/views/login/index'),
    hidden: true
  },

  // 3. 分享页（公开访问）
  {
    path: `${roterPre}/share/:id`,
    name: 'share',
    component: () => import('@/views/share'),
    hidden: true
  },

  // 4. 图标选择页（供 iframe 嵌入使用）
  {
    path: roterPre + '/setting/icons',
    component: () => import('@/components/form-common/select-icon.vue'),
    name: 'icons'
  },

  // 5. 图片上传页（供 iframe 嵌入使用）
  {
    path: roterPre + '/setting/uploadPicture',
    component: () => import('@/components/uploadPicture/index.vue'),
    name: 'uploadPicture'
  },

  // 6. 文件预览页
  {
    path: roterPre + '/openFile',
    component: () => import('@/components/openFile/index.vue'),
    name: 'previewPage',
    meta: { title: '文件预览' }
  },

  // 7. 错误页面
  { path: roterPre + '/401', component: () => import('@/views/error-page/401'), hidden: true },
  { path: roterPre + '/404', name: '404', component: () => import('@/views/error-page/404'), hidden: true },

  // 8. 低代码相关页面
  { path: roterPre + '/process', component: () => import('@/views/develop/crud/process.vue'), name: 'process' },
  { path: roterPre + '/event', component: () => import('@/views/develop/crud/event.vue'), name: 'event' },
  { path: roterPre + '/dashboard-design', component: () => import('@/views/system/dashboard-design/charts/index.vue'), name: 'dashboardDesign' },
]
```

**关键点说明：**
- 使用 `Layout` 组件的路由（如工作台），会显示完整的导航栏、侧边栏和顶部工具栏。
- 不使用 `Layout` 的路由（如登录页、分享页），是全屏独立页面。
- `hidden: true` 表示该路由不会出现在侧边栏菜单中。
- 使用箭头函数 `() => import(...)` 实现了路由级别的代码懒加载，只有在用户访问该路由时才加载对应的组件代码。

#### 3.2.2 modules/ 业务模块补充路由

`src/router/modules/` 定义了一些虽然属于业务功能、但不通过后端菜单管理的固定路由页面。这些页面通常是从其他页面跳转过来的详情页或子页面，按业务域一个模块一个文件：

```javascript
// src/router/modules/program.js
const programRouter = {
  path: `${roterPre}/program`,
  component: Layout,              // 使用整体布局
  name: 'program',
  hidden: true,                   // 只承载路由，不参与 permission_routes 菜单渲染
  meta: { title: '项目' },
  children: [
    {
      path: 'programList/taskDetails',
      component: () => import('@/views/program/programList/taskDetails.vue'),
      name: 'taskDetails',
      meta: { title: '项目详情' }
    },
    {
      path: 'programList/dynamics',
      component: () => import('@/views/program/programList/dynamics.vue'),
      name: 'dynamics',
      meta: { title: '项目动态' }
    }
  ]
};

export default programRouter;
```

每个模块文件 default 导出一条路由记录或一个路由记录数组（如 `setting.js` 导出的是几条不包 Layout 的全屏工具页），`modules/index.js` 会自动聚合。

**设计意图：** 将这些"子页面"路由按业务域拆到 `modules/` 中单独管理，一是避免它们需要通过后端菜单配置才能访问，二是让同一业务域的固定路由集中在一个文件里，新增模块不必再改动公共文件。例如"项目详情"页面通常是从项目列表页通过 `this.$router.push` 跳转过来的，它不需要出现在侧边栏菜单中。

> 不在后台菜单里的二级页，记得用 `meta.activeMenu` 指向所属列表页的完整路径，否则侧边栏不高亮、面包屑为空。

### 3.3 动态路由生成流程（核心）

这是整个路由系统中最重要的部分。动态路由的生成流程涉及多个文件的协作，下面按照完整的执行顺序逐步讲解。

#### 3.3.1 完整流程概览

```
用户登录
  ↓ 获得 token
浏览器刷新 / 首次访问需要权限的页面
  ↓
permission.js 路由守卫拦截
  ↓ 检查 token 存在 + 菜单为空
调用 getMenus()（src/utils/auth.js）
  ↓
请求后端接口 GET /api/ent/user/menus
  ↓ 返回 { menu: [...], roles: [...] }
store.commit('user/SET_MENU_LIST', menus)    → 保存菜单到 Vuex
store.commit('user/SET_PERMISSIONS', roles)  → 保存权限标识到 Vuex
  ↓
调用 getRouterMenus(menu)（src/router/index.js）
  ↓
removeItems()     → 移除不需要的菜单项
replaceMenuPath() → 预处理菜单路径
filterAsyncRoutes() → 递归转换为 Vue Router 路由配置
  ↓
将生成的路由 push 到 constantRoutes 数组
  ↓
resetRouter()     → 重置路由实例以加载新路由
  ↓
next(to.fullPath) → 重新导航到目标页面
```

#### 3.3.2 require.context 组件自动发现

这是动态路由能够工作的"秘密武器"。在 `src/router/index.js` 的最顶部，有以下代码：

```javascript
// 获取 views 中以 .vue 结尾的文件
const contextInfo = require.context('../views', true, /.vue$/, "lazy");

const filteredFileNames = () => {
  const files = {};
  contextInfo.keys().forEach((fileName) => {
    // 过滤掉 components 子目录中的文件（它们是局部组件，不是页面）
    if (!fileName.includes('/components')) {
      const path = '/' + fileName.substring(2, fileName.length - 4);
      files[path] = () => contextInfo(fileName)
    }
  });
  return files;
};
const files = filteredFileNames();
```

**原理详解：**

1. `require.context('../views', true, /.vue$/, "lazy")` 是 Webpack 提供的 API，作用是在编译时扫描 `src/views/` 目录下所有匹配 `.vue` 后缀的文件。
2. 第四个参数 `"lazy"` 表示使用懒加载模式——每个文件不会立即被导入，而是生成一个 `() => import('./xxx.vue')` 的函数，只在实际需要时才加载。
3. `filteredFileNames()` 函数过滤掉了路径中包含 `/components` 的文件（因为这些通常是页面级别的局部组件，不应该作为独立路由页面）。
4. 最终生成一个以文件路径为 key、以懒加载函数为 value 的对象，例如：

```javascript
{
  '/user/workbench/index': () => import('@/views/user/workbench/index.vue'),
  '/customer/list/index': () => import('@/views/customer/list/index.vue'),
  '/hr/attendance/index': () => import('@/views/hr/attendance/index.vue'),
  // ... 所有 views 下的 .vue 页面
}
```

当后端菜单数据中的 `component` 字段值为 `user/workbench/index` 时，路由系统会在 `files` 对象中查找 `/user/workbench/index`，拿到对应的懒加载函数作为路由的 `component`。

**这意味着：你只需在 `src/views/` 下创建 `.vue` 文件，然后在后端配置好菜单的 `component` 字段指向该文件路径，前端就会自动为它生成路由，无需手动编写任何路由配置。**

#### 3.3.3 getRouterMenus() — 动态路由入口函数

当 `auth.js` 中的 `getMenus()` 从后端获取菜单数据后，会调用此函数：

```javascript
export const getRouterMenus = (entMenuList) => {
  let entRouter = [];
  if (entMenuList && entMenuList.length > 0) {
    // 1. 移除不需要处理的菜单项（如"工作台"已在静态路由中定义）
    removeItems(entMenuList, ['/admin/user/work']);

    // 2. 预处理菜单路径结构
    replaceMenuPath(entMenuList, '/');

    // 3. 递归转换为 Vue Router 格式的路由配置
    entRouter = filterAsyncRoutes(entMenuList);

    // 4. 将动态路由追加到常量路由数组中
    constantRoutes.push(...entRouter, route404);

    // 5. 重置路由实例以使新路由生效
    resetRouter();
  }
};
```

每一步的详细说明如下。

#### 3.3.4 removeItems() — 菜单数据清理

```javascript
const removeItems = (items, paths) => {
  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    for (let j = 0; j < paths.length; j++) {
      const path = paths[j];
      if (item.menu_path === path) {
        items.splice(i, 1);  // 找到匹配项，从数组中移除
        i--;
        break;
      } else if (item.children) {
        removeItems(item.children, paths);  // 递归处理子菜单
        if (item.children.length === 0) {
          delete item.children;  // 如果子菜单被清空，删除 children 属性
        }
      }
    }
  }
};
```

此函数的作用是从后端返回的菜单树中移除指定路径的菜单项。例如"工作台"（`/admin/user/work`）已经在 `routes.js` 的静态路由中定义了，如果后端菜单中也返回了这个路径，就会导致路由重复注册。通过 `removeItems` 在处理前将其剔除。

#### 3.3.5 replaceMenuPath() — 路径预处理

```javascript
const replaceMenuPath = (menus, parentPath) => {
  menus.forEach((menu) => {
    if (menu.children) {
      replaceMenuPath(menu.children, menu.menu_path);
    }
    if (parentPath !== '/' && menu.menu_path && menu.menu_path.indexOf(parentPath) > -1) {
      menu.new_path = menu.menu_path.replace(parentPath + '/', '');
    }
    menu.component = '/' + menu.component;
  });
};
```

此函数完成两件事：
1. **路径裁剪**：如果子菜单的 `menu_path` 中包含父菜单的路径前缀，则将前缀部分去掉，生成相对路径存入 `new_path`。这是因为 Vue Router 的嵌套路由中，子路由的 `path` 应该是相对于父路由的相对路径。
2. **component 路径补全**：在 `component` 字段前加上 `/`，使其与 `files` 对象的 key 格式匹配（如 `user/list/index` 变为 `/user/list/index`）。

#### 3.3.6 createRouteRecord() — 路由记录工厂

这是路由生成的核心函数，它将一条菜单数据转换为一个 Vue Router 路由记录对象：

```javascript
const createRouteRecord = (route, firstRoute) => {
  const routeRecord = {
    path: firstRoute ? `/${route.menu_path}` : route.menu_path,
    name: route.unique_auth + '_' + generateUniqueString(),
    meta: {
      title: route.menu_name,
      icon: route.icon
    }
  };

  if (route.pid === 0) {
    // 顶级菜单：使用 Layout 布局组件
    routeRecord.component = Layout;
    delete routeRecord.name;  // 顶级路由不需要 name
  } else if (route.pid > 0 && route.children && route.children.length > 0) {
    // 中间层级（有子菜单的非顶级菜单）：渲染 router-view 作为子路由容器
    routeRecord.component = { render: (e) => e('router-view') };
  } else {
    // 叶子节点（最终页面）：从 files 对象中查找对应的 .vue 组件
    routeRecord.component = files[route.component];
  }
  return routeRecord;
};
```

**三种情况的处理逻辑：**

1. **`pid === 0`（顶级菜单）**：这些是一级菜单，它们的 `component` 设置为 `Layout`（即 `src/layout/index.vue`）。Layout 组件提供了导航栏、侧边栏和主内容区的整体框架，子路由的内容会渲染在 Layout 的 `<app-main />` 区域中。

2. **中间层级（pid > 0 且有 children）**：这类菜单本身不是一个具体页面，而是一个分类容器。例如"人事管理"下面有"考勤"、"薪资"等子菜单。它的 `component` 被设置为一个渲染函数 `{ render: (e) => e('router-view') }`，即直接渲染一个 `<router-view />`，让子路由的内容"穿透"显示。

3. **叶子节点（无 children 的具体页面）**：这是最常见的情况。系统从 `files` 对象中通过 `route.component` 字段查找对应的 `.vue` 文件懒加载函数。例如后端返回的 `component: "hr/attendance/index"` 会匹配到 `files['/hr/attendance/index']`，即 `() => import('@/views/hr/attendance/index.vue')`。

**`name` 字段的生成规则**：使用 `unique_auth`（权限标识）+ `_` + 一个唯一字符串拼接而成。这确保了每个路由 name 的唯一性，避免 Vue Router 的 name 冲突警告。

#### 3.3.7 resetRouter() — 路由热重载

```javascript
const createRouter = () =>
  new Router({
    mode: 'history',
    scrollBehavior: () => ({ y: 0 }),
    routes: constantRoutes
  });

const router = createRouter();

export function resetRouter() {
  const newRouter = createRouter();
  router.matcher = newRouter.matcher;  // 替换路由匹配器
}
```

由于 Vue Router 3.x 没有提供动态添加路由后立即生效的官方 API（`addRoutes` 方法存在已知问题），项目采用了"替换 matcher"的技巧：创建一个新的路由实例，然后用新实例的 `matcher` 替换当前路由实例的 `matcher`。这样新增的路由就会被新的 matcher 识别并正确匹配。

### 3.4 路由守卫详解

`src/permission.js` 是全局路由前置守卫，它决定了每次页面跳转时的认证和授权逻辑。下面逐段解析其代码：

```javascript
import router from './router'
import store from './store'
import NProgress from 'nprogress'
import 'nprogress/nprogress.css'
import getPageTitle from '@/utils/get-page-title'
import { roterPre } from '@/settings'
import { getMenus } from '@/utils/auth'
import { aiFloatEntryController } from "@/libs/ai"

NProgress.configure({ showSpinner: false })  // 关闭顶部进度条的转圈动画

// 白名单：这些路由名不需要登录即可访问
const whiteList = [`login`, `share`, '/auth-redirect', '404']
```

#### 3.4.1 守卫核心逻辑

```javascript
router.beforeEach(async (to, from, next) => {
  NProgress.start()  // 显示页面顶部的蓝色进度条
  document.title = getPageTitle(to.meta.title)  // 更新浏览器标签标题

  const hasToken = store.getters.token  // 从 Vuex 获取 token

  if (hasToken) {
    // ========== 已登录状态 ==========
    if (to.path === `${roterPre}/login`) {
      // 如果已登录还想访问登录页，直接跳转到首页
      next({ path: '/' })
      } else {
        // 判断是否是首次加载（刷新页面后 menuList 会被清空）
        if (store.getters.menuList.length <= 0) {
          // 首次加载：需要先从后端获取菜单并注入路由
          await getMenus()
          next({ ...to, replace: true }) // 路由表变更后重新匹配
          return
        }

        // 动态菜单准备完成后，再按最终路由状态确保 AI 悬浮球并同步显隐
        await aiFloatEntryController.ensure(store.getters.token, to.path)
        next()
      }
    NProgress.done()
  } else {
    // ========== 未登录状态 ==========
    if (whiteList.indexOf(to.name) !== -1) {
      // 目标页面在白名单中，允许访问
      next()
    } else {
      // 清空过期的缓存数据
      await store.dispatch('user/resetToken')
      // 跳转到登录页，并携带 redirect 参数记录原本要访问的页面
      next(`${roterPre}/login?redirect=${to.fullPath}`)
      NProgress.done()
    }
  }
})
```

**关键流程说明：**

1. **`store.getters.menuList.length <= 0` 的判断**：Vuex 中的 `menuList` 在页面刷新后会丢失（因为 Vuex 是内存存储）。所以每次刷新页面，这个条件都会为 `true`，从而触发重新获取菜单和注入路由的逻辑。这是一种"按需加载"的设计——只有在菜单数据不存在时才请求后端。

2. **`next(to.fullPath)` 而非 `next()`**：在动态注入路由后，必须使用 `next(to.fullPath)` 进行一次"重新导航"，让 Vue Router 用新的路由表重新匹配当前 URL。如果直接调用 `next()`，路由还没来得及注册，会导致 404。

3. **`redirect` 参数**：当未登录用户试图访问一个受保护页面时，系统会将该页面的路径记录在 URL 的 `redirect` 查询参数中。登录成功后，登录页会读取这个参数并跳转到用户原本想访问的页面。

### 3.5 菜单权限获取函数 getMenus()

此函数位于 `src/utils/auth.js`，是连接路由守卫与后端菜单接口的桥梁：

```javascript
export const getMenus = () => {
  return new Promise((resolve, reject) => {
    userMenusApi()                              // 调用后端接口 GET /api/ent/user/menus
      .then((response) => {
        const { menu, roles } = response.data;  // 解构获取菜单和权限数据

        const menus = JSON.parse(JSON.stringify(menu));  // 深拷贝菜单数据
        store.commit('user/SET_MENU_LIST', menus);       // 保存菜单到 Vuex（用于侧边栏渲染）
        store.commit('user/SET_PERMISSIONS', roles);     // 保存按钮级权限标识到 Vuex

        store.dispatch('user/getMember');      // 获取企业人员列表（缓存到 Vuex）
        store.dispatch('user/getDepartment');  // 获取部门列表（缓存到 Vuex）

        getRouterMenus(menu);                  // 将菜单数据转换为路由并注入

        resolve();
      })
      .catch((error) => {
        reject();
      });
  });
};
```

**注意深拷贝**：代码中使用 `JSON.parse(JSON.stringify(menu))` 对菜单数据做了深拷贝。这是因为 `getRouterMenus()` 函数内部会修改菜单对象（如 `replaceMenuPath` 会给对象添加 `new_path` 属性、修改 `component` 属性），如果不做深拷贝，Vuex 中保存的菜单数据也会被修改，导致侧边栏渲染异常。

### 3.6 二次开发实操：如何新增一个路由页面

#### 3.6.1 方式一：通过后端配置菜单（推荐）

这是最推荐的方式，也是项目设计的初衷。你只需完成两步：

**第一步：创建 Vue 页面文件**

在 `src/views/` 目录下按照功能模块创建页面文件。例如要新增一个"资产管理"模块：

```
src/views/
└── asset/                    # 新建功能模块目录
    └── list/
        └── index.vue         # 列表页
```

**第二步：在后端管理页面配置菜单**

在 OA 系统的后台管理中配置菜单项，核心字段为：
- **`menu_name`**：菜单显示名称，如"资产管理"
- **`menu_path`**：菜单路径，如 `/admin/asset/list`
- **`component`**：对应的前端组件路径，如 `asset/list/index`（对应 `src/views/asset/list/index.vue`）
- **`icon`**：菜单图标
- **`pid`**：父菜单 ID（0 表示一级菜单）

配置完成后，刷新前端页面，系统会自动从后端获取新的菜单数据，动态生成路由。无需修改任何前端路由配置文件。

#### 3.6.2 方式二：添加前端静态路由

如果某个页面不需要在侧边栏菜单中显示（如详情页、编辑页等从其他页面跳转过来的子页面），把路由加到对应业务模块文件 `src/router/modules/<module>.js` 的 `children` 数组中；该模块文件不存在时新建一个即可，无需改动 `router/index.js`：

```javascript
// 在 src/router/modules/asset.js 的 children 数组中添加
{
  path: 'detail',
  component: () => import('@/views/asset/detail/index.vue'),
  name: 'assetDetail',
  meta: {
    title: '资产详情',
    activeMenu: `${roterPre}/asset/list`   // 指向所属列表页，供菜单高亮与面包屑使用
  }
}
```

`modules/` 下的路由不需要后端配置，会在应用启动时自动注册。

## 第四章 Axios 请求封装与 API 管理

本项目的所有 HTTP 请求都经过 `src/api/request.js` 中封装的 Axios 实例发出。该封装层实现了请求去重、自动认证、统一响应处理和错误拦截等核心能力，是前后端数据交互的基石。

### 4.1 request.js 完整源码逐段解析

#### 4.1.1 Axios 实例创建

```javascript
import axios from 'axios'
import store from '@/store'
import router from '../router'
import SettingMer from '@/libs/settingMer'
import Tips from '@/utils/tips'
import { roterPre } from '@/settings'

const instance = axios.create({
  baseURL: SettingMer.https,   // 'http://xxx.com/api/ent'
  timeout: 60000               // 请求超时时间 60 秒
})
```

- **`baseURL`**：来自 `src/libs/settingMer.js` 中的 `https` 属性，值为「解析后的接口地址 + `/api/ent`」（接口地址取自 `@/config/env` 的 `BASE_API`，留空时回落到当前站点 origin）。所有请求的 URL 都会自动拼接此前缀。例如 `request.get('user/menus')` 的实际请求地址为 `http://xxx.com/api/ent/user/menus`。
- **`timeout`**：设置为 60 秒，比常见的 15 秒更长。这是因为 OA 系统中存在文件导入、批量操作等耗时较长的接口。

#### 4.1.2 请求去重机制

这是本项目 Axios 封装的一大特色。它通过 `pendingRequests` Map 来防止用户在短时间内重复触发同一个请求（例如快速双击按钮）：

```javascript
// 存储正在进行的请求（用于去重）
const pendingRequests = new Map()

// 生成请求唯一标识（基于方法、URL 和参数）
const generateRequestKey = (options) => {
  const { method, url, params, data } = options
  // GET 类请求用 params，其他用 data 作为参数标识
  let baseParams = ['get', 'head'].includes(method) ? params : data;
  let requestParams;
  if (baseParams instanceof FormData) {
    // FormData 类型：提取键值对（兼容分片上传）
    requestParams = {};
    for (const [key, value] of baseParams.entries()) {
      requestParams[key] = value instanceof File ? '[File]' : value;
    }
  } else {
    requestParams = baseParams;
  }
  // 序列化为字符串作为唯一 key
  return JSON.stringify({ method, url, params: requestParams })
}
```

**工作原理：** 每个请求发出前，先根据请求方法 + URL + 参数生成唯一的 key。如果 `pendingRequests` Map 中已存在相同 key 的请求（说明上一个相同请求还在进行中），则直接返回之前请求的 Promise，而不发起新的请求。请求完成后，从 Map 中删除该 key。

如果某个场景确实需要允许重复请求（如定时轮询），可以在调用时传入 `allowRepeat: true` 选项来绕过去重检查。

#### 4.1.3 认证头自动注入

```javascript
const token = store.getters.token
const unique = localStorage.getItem('unique')
const headers = options.headers || {}
const lang = store.getters.lang || 'zh-cn'

if (token) {
  headers['Authorization'] = 'Bearer ' + token   // JWT 认证
}
if (unique && router.app._route && router.app._route.name === 'share') {
  headers['Curd-Unique'] = unique                 // 分享页面的匿名标识
}
headers['laravel_lang'] = lang                    // 后端国际化语言标识
```

每个请求都会自动携带三个头信息：
- **`Authorization`**：Bearer Token 格式的 JWT 认证令牌，从 Vuex 中获取。
- **`Curd-Unique`**：仅在调查问卷/分享页面时携带，用于匿名用户的身份标识。
- **`laravel_lang`**：发送给后端的语言标识，后端据此返回对应语言的响应消息。

#### 4.1.4 统一响应处理

```javascript
instance(options)
  .then((res) => {
    const data = res.data || {}

    if (res.status !== 200) {
      return reject({ message: '请求失败', res, data })
    }
    // Token 失效状态码集合
    else if ([410000, 410001, 410002, 40000, 410003].indexOf(data.status) !== -1) {
      store.dispatch('user/resetToken').then(() => {
        if (location.pathname !== '/admin/login') {
          location.href = `${roterPre}/login?redirect=${location.pathname}`
        }
      })
    }
    // 业务成功
    else if (data.status === 200) {
      if (data.tips && data.message !== 'ok') {
        Tips.msgSuccess(data.message)    // 自动显示成功提示
      }
      return resolve(data)
    }
    // 业务错误
    else if (data.status === 400) {
      if (data.tips && data.message !== 'error') {
        Tips.msgError(data.message)      // 自动显示错误提示
      }
      return resolve(data, res)          // 注意：400 也是 resolve，由调用方处理
    }
    else {
      return reject({ message: data.message, res, data })
    }
  })
```

**关键设计决策解读：**

1. **状态码 `410000/410001/410002/40000/410003`**：这些是后端定义的 Token 过期/ 无效/ 被踢出等状态码。一旦检测到，系统会自动清空本地 Token 并跳转到登录页。这意味着你在编写业务代码时**无需单独处理 Token 过期**，框架会自动兜底。

2. **`data.tips` 字段**：后端可以通过此字段控制前端是否自动显示提示消息。当 `data.tips` 为 `true` 时前端会自动弹出 `ElMessage` 提示，`false` 时则静默处理。这是一种前后端协作的消息提示模式。

3. **状态码 `400` 使用 `resolve` 而非 `reject`**：这是一个重要的设计决策。业务错误（如"该名称已存在"）使用 `resolve` 返回，调用方可以通过 `data.status` 判断业务是否成功，而不会触发 `.catch()`。只有 HTTP 级别的错误和未知错误才使用 `reject`。

#### 4.1.5 请求方法快捷封装

```javascript
const request = ['post', 'put', 'patch', 'delete'].reduce((request, method) => {
    request[method] = (url, data = {}, options = {}) => {
      return baseRequest(Object.assign({ url, data, method }, defaultOpt, options))
    }
    return request
  }, {})

;['get', 'head'].forEach((method) => {
  request[method] = (url, params = {}, options = {}) => {
    return baseRequest(Object.assign({ url, params, method }, defaultOpt, options))
  }
})
```

这段代码将 HTTP 方法封装为简洁的调用方式：
- **GET/HEAD** 类型：第二个参数为 `params`（URL 查询参数）
- **POST/PUT/PATCH/DELETE** 类型：第二个参数为 `data`（请求体数据）

## 第五章 Vuex 状态管理

### 5.1 Store 架构设计

#### 5.1.1 自动注册机制

`src/store/index.js` 使用 Webpack 的 `require.context` 实现了 Store 模块的**自动注册**：

```javascript
import Vue from 'vue';
import Vuex from 'vuex';
import getters from './getters';

Vue.use(Vuex);

const modulesFiles = require.context('./modules', true, /\.js$/);
const modules = modulesFiles.keys().reduce((modules, modulePath) => {
  const moduleName = modulePath.replace(/^\.\/(.*)\.\w+$/, '$1');  // './app.js' → 'app'
  const value = modulesFiles(modulePath);
  modules[moduleName] = value.default;
  return modules;
}, {});

const store = new Vuex.Store({
  modules,
  getters,
});

export default store;
```

**这意味着：你只需在 `src/store/modules/` 目录下新建一个 `.js` 文件，导出一个标准的 Vuex 模块对象，它就会被自动注册为 Vuex 模块。** 文件名即为模块名。例如创建 `asset.js`，就会注册一个名为 `asset` 的命名空间模块。

## 第六章 权限控制体系

本系统实现了**三层权限控制**：路由级权限（控制用户能访问哪些页面）、按钮级权限（控制用户能看到/操作哪些按钮）和角色级权限（基于角色的通用控制）。三者协同工作，构成了完整的前端权限体系。

### 6.1 权限体系全景图

```
┌─────────────────────────────────────────────────────────┐
│  路由级权限                                              │
│  实现方式：permission.js 路由守卫 + 后端动态菜单           │
│  控制粒度：页面级别                                       │
│  效果：用户只能访问后端分配给他的菜单对应的页面              │
├─────────────────────────────────────────────────────────┤
│  按钮级权限（v-hasPermi 指令）                            │
│  实现方式：自定义指令 + store.getters.permissions          │
│  控制粒度：DOM 元素级别                                   │
│  效果：无权限的按钮从 DOM 中移除（不是隐藏，是删除）         │
├─────────────────────────────────────────────────────────┤
│  角色级权限（v-permission 指令）                           │
│  实现方式：自定义指令 + store.getters.roles               │
│  控制粒度：DOM 元素级别                                   │
│  效果：不属于指定角色的元素从 DOM 中移除                    │
└─────────────────────────────────────────────────────────┘
```

### 6.2 路由级权限实现

路由级权限已在第三章详细说明。核心原理是：后端只返回当前用户有权访问的菜单，前端根据菜单数据动态生成路由。用户无权访问的页面根本不会被注册为路由，因此即使用户在浏览器中手动输入 URL，也会被路由守卫拦截到 404 页面。

### 6.3 按钮级权限实现详解（v-hasPermi）

#### 6.3.1 指令源码解析

文件：`src/directive/permission/hasPermi.js`

```javascript
import store from '@/store';

export default {
  inserted(el, binding, vnode) {
    const { value } = binding;                    // 获取指令绑定的值
    const all_permission = '*';                   // 超管通配符
    const permissions = store.getters && store.getters.permissions;
    // permissions 是后端返回的权限标识数组，如 ['enterprise:admin:list', 'enterprise:admin:delete']

    if (value && value instanceof Array && value.length > 0) {
      const permissionFlag = value;               // 当前按钮所需的权限标识

      const hasPermissions = permissions.some((permission) => {
        // 如果用户是超管（拥有 * 权限），或者权限数组中包含当前按钮所需的权限标识
        return all_permission === permission || permissionFlag.includes(permission);
      });

      if (!hasPermissions) {
        // 没有权限：直接从 DOM 中移除该元素
        el.parentNode && el.parentNode.removeChild(el);
      }
    } else {
      throw new Error(`请设置操作权限标签值`);
    }
  },
};
```

**关键设计要点：**

1. **使用 `inserted` 钩子而非 `bind`**：`inserted` 钩子在元素被插入到父节点之后触发，此时 `el.parentNode` 一定存在，可以安全地调用 `removeChild`。
2. **移除而非隐藏**：使用 `removeChild` 从 DOM 树中物理删除元素，而非设置 `display: none`。这样更安全，因为隐藏的元素仍然可以通过浏览器开发工具被找到和使用。
3. **超管通配符 `*`**：如果用户的权限数组中包含 `*`，则表示拥有所有权限，任何按钮都不会被移除。

#### 6.3.2 权限数据的来源

权限标识数组在登录后通过 `getMenus()` 函数从后端获取，存储路径为：

```
后端接口 GET /api/ent/user/menus
  → response.data.roles     // 权限标识数组
  → store.commit('user/SET_PERMISSIONS', roles)
  → store.getters.permissions
```

后端返回的 `roles` 数据结构是一个字符串数组，例如：

```javascript
['enterprise:admin:list', 'enterprise:admin:create', 'enterprise:admin:delete', 'client:customer:list']
```

每个字符串由**冒号分隔的多级标识**组成，通常格式为 `模块:功能:操作`。

#### 6.3.3 使用示例

```html
<!-- 只有拥有 'enterprise:admin:delete' 权限的用户才能看到此按钮 -->
<el-button
  v-hasPermi="['enterprise:admin:delete']"
  type="danger"
  @click="handleDelete(row)"
>
  删除
</el-button>

<!-- 同时需要多个权限中的任意一个 -->
<el-button
  v-hasPermi="['enterprise:admin:create', 'enterprise:admin:edit']"
  type="primary"
  @click="handleEdit(row)"
>
  编辑
</el-button>
```

**注意事项：**
- 指令的值**必须是数组**，即使只有一个权限标识也要用数组包裹。
- 权限检查使用的是 `includes` 方法，即只要用户拥有数组中的**任意一个**权限就算有权限（OR 逻辑）。
- 由于指令在 `inserted` 阶段执行，它只会在元素首次插入时检查一次权限。如果权限数据动态变化（通常不会），需要通过 `v-if` 配合实现。

### 6.4 角色级权限（v-permission）

文件：`src/directive/permission/permission.js`

```javascript
import store from '@/store';

export default {
  inserted(el, binding, vnode) {
    const { value } = binding;
    const roles = store.getters && store.getters.roles;

    if (value && value instanceof Array && value.length > 0) {
      const permissionRoles = value;

      const hasPermission = roles.some((role) => {
        return permissionRoles.includes(role);
      });

      if (!hasPermission) {
        el.parentNode && el.parentNode.removeChild(el);
      }
    } else {
      throw new Error(`need roles! Like v-permission="['admin','editor']"`);
    }
  },
};
```

与 `v-hasPermi` 的区别在于数据来源不同：`v-permission` 使用的是 `store.getters.roles`（角色列表），而 `v-hasPermi` 使用的是 `store.getters.permissions`（权限标识列表）。在本系统中，**`v-hasPermi` 使用频率更高**，因为权限标识的粒度更细。

`src/libs/modal-form.js` 是本项目最具特色的工具之一，它实现了**后端定义表单结构、前端自动渲染**的能力。调用方式极为简洁——只需传入一个返回表单规则的 API Promise，就能弹出一个完整的表单弹窗。

只需一行代码就能完成"弹窗 + 表单 + 校验 + 提交"的完整流程。

#### 9.1.2 工作原理

1. 前端调用后端的 "获取表单" 接口（如 `GET /api/ent/bill_cate/create`）
2. 后端返回 `form-create` 格式的 JSON 规则，包含表单字段定义（`rule`）、表单配置（`config`）、提交地址（`action`）和提交方法（`method`）
3. `modal-form.js` 使用 `form-create` 库将 JSON 规则渲染为 Element-UI 表单
4. 用户填写表单后点击确认，自动调用 `action` 指定的 API 提交数据

```javascript
// modal-form.js 核心逻辑（简化版）
export default function modalForm(formRequestPromise) {
  return new Promise((resolve, reject) => {
    formRequestPromise.then(({ data }) => {
      // data 包含：title, rule, config, action, method
      this.$msgbox({
        title: data.title,
        message: h('formCreate', {
          props: { rule: data.rule, option: data.config }
        }),
        beforeClose: (action, instance, done) => {
          if (action === 'confirm') {
            fApi.submit((formData) => {
              // 自动提交到 data.action 指定的 API
              request[data.method.toLowerCase()](data.action, formData)
                .then(res => { done(); resolve(res); })
            })
          }
        }
      })
    })
  })
}
```

### 9.3 WebSocket 消息推送：notice.js

`src/libs/notice.js`（161 行）实现了基于 WebSocket 的实时消息推送功能。

**核心功能：**
- 建立 WebSocket 连接（`ws://域名/ws?type=ent&token=xxx`）
- 每 10 秒发送心跳 `ping` 包保持连接
- 接收 `notice` 类型的消息，播放提示音并弹出 Element-UI Notification
- 支持断线自动重连（最多 40 次，每次间隔 10 秒）
- 消息推送的操作按钮支持自定义回调

```javascript
function notice(token) {
  const protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:';
  const wsUrl = `${protocol}//${window.location.host}/ws?type=ent&token=${token}`;
  const ws = new WebSocket(wsUrl);

  ws.onopen = () => {
    // 每 10 秒发送心跳
    pingInterval = setInterval(() => send('ping'), 10000)
  }

  ws.onmessage = (res) => {
    const data = JSON.parse(res.data)
    if (data.type === 'notice') {
      audioTip.play()              // 播放提示音
      showNotification(data.data)  // 弹出通知
    }
  }

  ws.onclose = () => reconnect()   // 断线重连

  return () => ws.close()          // 返回关闭函数
}
```

```vue
        this.total = res.data.count
      }
      this.loading = false
    },
    // 搜索
    handleSearch() {
      this.pagination.page = 1
      this.getList()
    },
    // 重置
    handleReset() {
      this.searchForm = { keyword: '', status: '' }
      this.handleSearch()
    },
    // 新增
    handleAdd() {
      this.editId = null
      this.dialogTitle = '新增资产'
      this.dialogVisible = true
    },
    // 编辑
    handleEdit(row) {
      this.editId = row.id
      this.dialogTitle = '编辑资产'
      this.form = { name: row.name, code: row.code, category: row.category, remark: row.remark }
      this.dialogVisible = true
    },
    // 删除
    handleDelete(row) {
      this.$modalSure(`确定要删除资产"${row.name}"吗`).then(async () => {
        const res = await assetDeleteApi(row.id)
        if (res.status === 200) {
          this.$message.success('删除成功')
          this.getList()
        }
      })
    },
    // 提交
    handleSubmit() {
      this.$refs.form.validate(async (valid) => {
        if (!valid) return
        this.submitLoading = true
        const apiCall = this.editId
          ? assetUpdateApi(this.editId, this.form)
          : assetCreateApi(this.form)
        const res = await apiCall
        if (res.status === 200) {
          this.$message.success(this.editId ? '修改成功' : '创建成功')
          this.dialogVisible = false
          this.getList()
        }
        this.submitLoading = false
      })
    },
    // 重置表单
    resetForm() {
      this.form = { name: '', code: '', category: '', remark: '' }
      this.$refs.form && this.$refs.form.resetFields()
    }
  }
}
</script>
```

### 11.2 部署要点

#### 11.2.1 Nginx 配置

由于项目使用了 `history` 路由模式且路径前缀为 `/admin`，Nginx 必须配置 `try_files` 来支持前端路由的 URL 直接访问和刷新：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /path/to/dist;
    index index.html;

    # 关键配置：支持 history 路由模式
    location /admin {
        try_files $uri $uri/ /index.html;
    }

    # API 代理转发到后端
    location /api {
        proxy_pass http://backend-server:port;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket 代理
    location /ws {
        proxy_pass http://backend-server:port;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 上传文件访问
    location /uploads {
        proxy_pass http://backend-server:port;
    }

    # 启用 Gzip 压缩
    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml;
    gzip_vary on;
}
```

**注意事项：**
- `try_files $uri $uri/ /index.html` 是让所有 `/admin/xxx` 路径都回退到 `index.html`，由前端 Vue Router 处理路由。
- WebSocket 的代理需要添加 `Upgrade` 和 `Connection` 头部，否则无法建立 WebSocket 连接。
- 建议开启 Gzip 压缩，可将 JS/CSS 体积减少 60%-70%。

### A.1 常见开发问题与解决方案

| # | 问题描述 | 原因分析 | 解决方案 |
|---|---|---|---|
| 1 | 新增的页面路由不生效 | 后端未配置菜单，或 `component` 路径不匹配 | 检查后端菜单配置的 `component` 字段是否与 `src/views/` 下的文件路径一致 |
| 2 | `v-hasPermi` 不生效 | 指令值未传数组 | 确保值为数组格式 `['xxx:yyy']`，而非字符串 |
| 3 | 接口请求被去重拦截 | 短时间内触发了两次相同的请求 | 如有必要，传入 `{ allowRepeat: true }` 选项 |
| 4 | 页面刷新后菜单消失片刻后恢复 | Vuex 状态需从后端重新加载 | 正常现象，可添加全局 Loading 优化体验 |
| 5 | 修改了主题色但没生效 | 修改的文件不正确 | 只需修改 `src/styles/element-variables.scss` 中的 `$--color-primary` |
| 6 | 生产环境页面刷新 404 | Nginx 未配置 `try_files` | 参照 11.2.1 节配置 Nginx |
| 7 | WebSocket 连接失败 | 代理配置不正确 | 确保 `vue.config.js` 或 Nginx 中的 WebSocket 代理配置了 `ws: true` |
| 8 | Element-UI 样式穿透无效 | 未使用 `::v-deep` | 在 `<style scoped>` 中使用 `::v-deep .el-xxx {}` |
| 9 | `this.$modalForm` 弹窗为空 | 后端接口未返回 `form-create` 规则 | 确认后端接口返回了正确的 `rule` + `config` + `action` 字段 |
| 10 | 新增的 Store 模块不生效 | 忘记设置 `namespaced: true` | 确保模块导出对象包含 `namespaced: true` |
