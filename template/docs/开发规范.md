## 一、代码风格规范

### 1.1 Prettier 配置

项目使用 Prettier 进行代码格式化，核心配置如下：

```javascript
// .prettierrc.js
module.exports = {
  printWidth: 120,      // 一行最多 120 字符
  tabWidth: 2,          // 使用 2 个空格缩进
  useTabs: false,       // 不使用 tab 缩进
  semi: false,          // 语句末尾不加分号
  singleQuote: true,    // 使用单引号
  trailingComma: 'none', // 末尾不加逗号
  bracketSpacing: true, // 对象大括号内加空格
  arrowParens: 'always', // 箭头函数参数始终加括号
  endOfLine: 'lf'       // 使用 lf 换行符
}
```

### 1.2 ESLint 规则

项目使用 babel-eslint 解析器，核心规则：

- **缩进**: 2 空格
- **引号**: 使用单引号
- **分号**: 不强制要求（Prettier 控制为不加分号）
- **console**: 开发环境允许，生产环境建议移除

## 五、API 接口调用规范

### 5.1 request 封装说明

项目在 `src/api/request.js` 中封装了 Axios，提供以下特性：

- **请求去重**: 自动拦截短时间内重复请求
- **自动认证**: 自动携带 Token
- **统一响应处理**: 自动处理 Token 过期、错误提示
- **快捷方法**: `request.get/post/put/delete`

### 5.2 API 文件编写规范

## 六、Vuex 状态管理规范

### 6.1 模块自动注册

Store 模块通过 `require.context` 自动注册，新建模块只需：

1. 在 `src/store/modules/` 下创建 `.js` 文件
2. 导出标准 Vuex 模块对象
3. **必须设置 `namespaced: true`**

### 6.2 Store 模块结构

```javascript
// src/store/modules/asset.js
const state = {
  assetList: [],
  currentAsset: null
}

const mutations = {
  // 使用大写下划线命名
  SET_ASSET_LIST: (state, list) => {
    state.assetList = list
  },
  SET_CURRENT_ASSET: (state, asset) => {
    state.currentAsset = asset
  }
}

const actions = {
  // 获取资产列表
  async fetchAssetList({ commit }, params) {
    const { assetListApi } = await import('@/api/asset')
    const res = await assetListApi(params)
    if (res.status === 200) {
      commit('SET_ASSET_LIST', res.data.list)
    }
    return res
  }
}

// 必须设置命名空间
export default {
  namespaced: true,
  state,
  mutations,
  actions
}
```

### 6.3 在组件中使用 Store

```javascript
import { mapState, mapActions, mapMutations } from 'vuex'

export default {
  computed: {
    // 使用 mapState
    ...mapState('asset', ['assetList', 'currentAsset']),
    
    // 或通过 getters
    assetList() {
      return this.$store.getters.assetList
    }
  },
  
  methods: {
    // 使用 mapActions
    ...mapActions('asset', ['fetchAssetList']),
    
    // 使用 mapMutations
    ...mapMutations('asset', ['SET_CURRENT_ASSET']),
    
    // 直接调用
    async getList() {
      await this.fetchAssetList({ page: 1 })
    }
  }
}
```

### 6.4 添加全局 Getters

## 七、路由配置规范

### 7.1 动态路由（推荐）

大多数业务页面应通过后端菜单配置实现动态路由：

**步骤**:
1. 在 `src/views/` 下创建页面文件
2. 在后端管理界面配置菜单
3. 配置 `component` 字段指向文件路径

**后端菜单配置字段**:

| 字段 | 说明 | 示例 |
|------|------|------|
| menu_name | 菜单名称 | 资产管理 |
| menu_path | 菜单路径 | /admin/asset/list |
| component | 组件路径 | asset/list/index |
| icon | 菜单图标 | asset |
| pid | 父菜单ID | 0（一级菜单） |

### 7.2 静态路由

以下场景使用静态路由：

- 登录页、错误页、公开访问的分享页 → `src/router/routes.js`
- 不需要显示在菜单中的详情页、编辑页 → 按业务模块放到 `src/router/modules/<module>.js`

`src/router/modules/` 下的文件由 `modules/index.js` 通过 `require.context` 自动聚合，新增模块只需新建文件，无需改动 `router/index.js`。

```javascript
// src/router/modules/user.js
const userRouter = {
  path: `${roterPre}/user`,
  name: 'users',
  component: Layout,
  children: [
    {
      path: 'resume',
      component: () => import('@/views/user/resume/index'),
      name: 'resume',
      meta: { title: '我的简历' }
    }
  ]
}
```

```javascript
{
```

## 八、权限控制规范

### 8.1 权限体系

系统实现三层权限控制：

| 层级 | 实现方式 | 控制粒度 |
|------|----------|----------|
| 路由级 | 后端动态菜单 | 页面级别 |
| 按钮级 | v-hasPermi 指令 | DOM 元素 |
| 角色级 | v-permission 指令 | DOM 元素 |

### 8.2 按钮级权限（v-hasPermi）

```vue
<template>
  <!-- 单个权限 -->
  <el-button v-hasPermi="['asset:create']" type="primary" @click="handleAdd">
    新增
  </el-button>

  <!-- 多个权限（满足任一即可） -->
  <el-button v-hasPermi="['asset:edit', 'asset:admin']" @click="handleEdit">
    编辑
  </el-button>

  <!-- 删除按钮 -->
  <el-button v-hasPermi="['asset:delete']" type="danger" @click="handleDelete">
    删除
  </el-button>
</template>
```

**注意事项**:
- 指令值**必须是数组**
- 使用 `includes` 逻辑（满足任一权限即显示）
- 无权限时元素从 DOM 中**移除**（非隐藏）

### 8.3 角色级权限（v-permission）

```vue
<template>
  <!-- 仅管理员可见 -->
  <div v-permission="['admin']">
    管理员专属内容
  </div>

  <!-- 管理员或财务可见 -->
  <div v-permission="['admin', 'finance']">
    敏感数据
  </div>
</template>
```

### 8.4 权限标识命名规范

权限标识采用 `模块:功能:操作` 格式：

```
asset:list      # 资产列表
asset:create    # 新增资产
asset:edit      # 编辑资产
asset:delete    # 删除资产
asset:export    # 导出资产
asset:admin     # 资产管理（最高权限）
```

### 8.5 编程式权限判断

```javascript
export default {
  methods: {
    handleAction() {
      // 获取权限列表
      const permissions = this.$store.getters.permissions
      
      // 判断是否有权限
      if (permissions.includes('asset:admin')) {
        // 有权限执行
      } else {
        this.$message.warning('无操作权限')
      }
    }
  }
}
```

## 十、Git 提交规范

### 10.1 分支命名

| 分支类型 | 命名格式 | 示例 |
|----------|----------|------|
| 功能分支 | feature/功能名 | feature/user-management |
| 修复分支 | fix/问题描述 | fix/login-error |
| 发布分支 | release/版本号 | release/v2.3.0 |
| 热修复分支 | hotfix/问题描述 | hotfix/security-patch |

### 10.2 Commit Message 格式

```
<type>(admin[-<module>]): <subject>

<body>

<footer>
```

### 10.3 Type 类型

| 类型 | 说明 | 示例 |
|------|------|------|
| feat | 新功能 | feat(admin-user): 新增用户导入功能 |
| fix | 修复 Bug | fix(admin-login): 修复登录验证码失效问题 |
| docs | 文档更新 | docs(admin): 更新开发规范文档 |
| style | 代码格式（不影响功能） | style(admin): 格式化代码缩进 |
| refactor | 重构代码 | refactor(admin-api): 重构请求封装 |
| perf | 性能优化 | perf(admin-list): 优化列表渲染性能 |
| test | 测试相关 | test(admin-user): 添加用户模块单元测试 |
| chore | 构建/工具变动 | chore(admin): 更新依赖版本 |
| revert | 回滚提交 | revert(admin-user): 回滚用户模块修改 |

